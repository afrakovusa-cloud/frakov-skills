# Наши наработки: что уже написано и зачем

Это вторая часть репозитория. `README` объясняет, как всё поставить; здесь — что мы прошли сами
и какие шишки собрали, чтобы вам не пришлось.

Базовый плагин (`core/`) можно использовать как угодно. Ниже — надстройки, которые мы писали под
конкретные задачи; их можно брать как есть или как образцы для своих скриптов.

---

## 1. Ядро: корзина и весь аккаунт запросами

`core/magnit_api.py` — 40 команд, 130+ известных путей API (`docs/API_MAP.md`).

Что выяснилось по ходу:

- API ходит на `https://magnit.ru/webgate` + путь. Обязателен заголовок `x-service: express`;
  для превью заказа ещё `x-delivery-type: delivery`.
- Авторизация — не логин с паролем, а **заголовки и куки живой сессии**. Один снимок браузером
  даёт недели работы.
- Корзина читается и меняется одним PUT тела `{items}` — секунды вместо минут.
- У каждого ответа цена и остаток привязаны к точке (`shopCode`, `x-store-code`), а не к аккаунту.

## 2. Страж цен — `examples/magnit_watch.py`

Сравнивает сегодняшнюю цену с медианой прошлых дней и пишет, только когда реально подешевело.

Правила, выведенные из практики:

- нужно ≥3 прошлых дня — иначе «обычная» цена неизвестна, и скрипт молчит;
- падение = ниже медианы больше чем на порог (по умолчанию 15%);
- повтор той же цены не присылается (state-файл), а падение ещё ниже — присылается снова;
- наполняет журнал `--snapshot` по расписанию (`cron`/`systemd-timer`, раз в день).

Запуск:

```bash
python3 core/magnit_api.py --snapshot        # записать сегодняшние цены
python3 examples/magnit_watch.py             # проверить, что подешевело
```

## 3. Сравнение цен по магазинам — `--compare`

Одна из самых полезных вещей на практике: **разница по точкам одного города доходит до 5–29%**.
`--compare "товар"` берёт ближайшие магазины к вашему адресу и сравнивает одну и ту же позицию.

Что важно: корзина не пересчитывается при смене точки — за товаром закрепляется та цена, что была
при добавлении. Поэтому сначала выбирайте точку, потом кладите товар.

## 4. Добавление по прямым ссылкам — `tools/magnit_add_by_url.py`

Поиск «по слову» жмёт первую кнопку «В корзину» и врёт, если страница не догрузилась. Здесь
товар открывается карточкой по URL, а результат сверяется через API: выросло ли число позиций.

Это общее правило, которое стоит перенести в свои скрипты: **любое действие подтверждать
чтением состояния**, а не словами «добавлено».

## 5. Что реально продаётся в моей точке — `tools/magnit_search_ui.py`

Нужно, когда API кладёт товар, а в корзине 0 шт. Открывает страницу поиска в контексте вашей
точки доставки и печатает карточки с признаком наличия.

## 6. Браузерный запасной путь — `tools/magnit_cart.py`

Полный цикл кликами: выбрать точку доставки, нажать «В корзину», снять скриншот. Медленнее
(минуты), зато работает, когда API-снимок недоступен. Требует экран (или `xvfb-run`).

## 7. Разведка новых путей API — `core/magnit_search_probe.py`

Ловит XHR, которым сайт ищет товары, и печатает адрес и тело запроса. Это метод, которым
собрана вся карта: включаете в DevTools запись, делаете действие руками, ищете запрос по слову
из ответа, повторяете через `requests` с теми же заголовками.

## Что мы сознательно не выложили

- **Оформление заказа.** Черновик отдаёт 422, следующий шаг — списание денег. Слишком большая
  цена ошибки в чужом аккаунте. Превью заказа есть, кнопки «купить» нет.
- **Генератор промо-сторис** — ему нужен ключ платного сервиса картинок, к Магниту отношения
  не имеет.
- **Личные данные** — куки, адрес доставки, коды своих магазинов, логи. Всё это лежит только в
  `~/.magnit/` и в репозиторий не попадает.

## Идеи, которые мы не стали делать (берите, если нужно)

- Уведомления о подешевевшем товаре в Telegram (сам страж уже умеет отправлять строку).
- Сравнение одинаковых корзин между сетями (Магнит/Пятёрочка/Лента) — дорого по точкам, но
  данные в API открытые.
- История своей корзины: что покупаешь регулярно и на сколько выросли цены за месяц. Журнал
  цен уже пишется, остаётся сводка.
