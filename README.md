# frakov-skills

Скиллы для Claude Code, которые я сделал под свою работу и которыми делюсь.
Python 3 без зависимостей, лицензия MIT.

## Скиллы

| Скилл | Что делает | Запуск |
|---|---|---|
| [`dev-route`](skills/dev-route/) | Ведёт разработку приложения по 8 этапам: голосовой бриф → исследование → прожарка вопросами → PRD со словарём и критериями готовности → второе мнение → чек-лист и сборка → приёмка → бэклог. Скрипт не пускает на следующий этап, пока в текущем есть незакрытый пункт. | «разработка», «новое приложение» |
| [`grilling`](skills/grilling/) | Прожарка плана или идеи: агент задаёт вопросы раундами, у каждого свой рекомендованный ответ, пока не останется нерешённых развилок. Нужен для `dev-route` (этап 3), работает и сам по себе. | «прожарь», «grill me» |
| [`business`](skills/business/) | Ведёт бизнес как проверяемую машину из 5 узлов: стратегия → оффер/привлечение → операции → финансы → люди/масштаб. Каждый совет опирается на текст конкретной книги (grep по `references/source-book/`, а не память модели), каждой цифре ставится метка «факт / оценка / гипотеза», а скрипт `check_facts.py` не даёт отправить план с непроверенным «фактом». Плюс российские налоги и комплаенс, юнит-экономика, сценарии и Монте-Карло, готовый HTML-план. | «бизнес», «бизнес-план», «юнит-экономика», «налоги», «УСН» |

## Плагины

Не скиллы, а самостоятельные CLI-инструменты. Claude для работы не нужен.

| Плагин | Что делает |
|---|---|
| [`magnit`](plugins/magnit/) | Неофициальный клиент HTTP API доставки «Магнит»: корзина, поиск товаров, цены по ближайшим магазинам, слоты доставки, акции и баллы. Браузер нужен один раз — снять заголовки и куки живой сессии, дальше обычные `requests`. |

## Установка

Скопировать папку скилла в `~/.claude/skills/` (для всех проектов) или в `.claude/skills/` проекта:

```bash
git clone https://github.com/afrakovusa-cloud/frakov-skills.git
cp -R frakov-skills/skills/dev-route frakov-skills/skills/grilling frakov-skills/skills/business ~/.claude/skills/
```

Перезапустить Claude Code — скиллы появятся в каталоге. Для `dev-route` и `business` нужен Python 3 (только стандартная библиотека).
Проверка забора: `python3 ~/.claude/skills/dev-route/scripts/test_route.py` → `ok`.
Проверка фактов в бизнес-плане: `python3 ~/.claude/skills/business/scripts/check_facts.py <файл>` → код 0.

## Как устроен `dev-route`

- **Три трека:** `full` — все 8 этапов; `lite` — мини-приложение на вечер (без исследования и второго мнения);
  `feature` — новая фича в живой проект.
- **Забор:** в папке проекта лежит `ROUTE.md` с чекбоксами. Перед этапом агент запускает `route.py gate` —
  есть открытый пункт в прошлых этапах → стоп. Последний пункт каждого этапа закрывает только человек словами «этап закрыт».
- **Документы проекта:** `BRIEF.md`, `RESEARCH.md`, `GRILL.md`, `PRD.md`, `CONTEXT.md` (словарь), `PHILOSOPHY.md`,
  `REVIEW.md`, `CHECKLIST.md`, `tasks/`, `BACKLOG.md`.
- **Приёмка:** тесты пишет не исполнитель, тест обязан краснеть на откате фикса, критик ≤ 3 кругов,
  все изменения сверяются с чек-листом (лишнее без спроса не проходит), каждый сценарий PRD прокликан.

## Как устроен `business`

- **Пять узлов:** стратегия → оффер/привлечение → операции → финансы → люди/масштаб. «Не растёт / не зарабатывает» →
  узлы проходятся по порядку: нет спроса важнее плохих операций, дырявая юнит-экономика убивает раньше стратегии.
- **Опора на первоисточник, не на память.** В `references/source-book/` лежат тексты книг канона
  (Hormozi, Rumelt, Goldratt, Collins, Horowitz, Reichheld и др.). Нужен факт или цитата — скилл ищет grep по тексту,
  карта «тезис → книга» в `references/source-map.md`. Нет опоры в тексте — так и говорит: «в каноне этого нет»,
  а не выдаёт память модели за книгу. Термины ищутся по одному слову: замер показал, что из 50 составных терминов
  28 в книгах не встречаются ни разу, а те же слова по отдельности живые почти все.
- **Каждое утверждение помечено:** `факт (источник, дата)` / `оценка` / `гипотеза`. Закон или штраф — только по тексту
  самого акта, цена — по ≥ 2 живым объявлениям, иначе «оценка». Перед отправкой плана гоняется
  `scripts/check_facts.py`: строка «факт» без источника или закон без сверки → код ≠ 0, править до нуля.
- **Маршрут по задаче:** таблица в `SKILL.md` ведёт к нужному файлу — `references/functions/` (стратегия, оффер,
  финансы, операции, конкуренты, налоги РФ, комплаенс РФ, найм), `references/playbooks/` (план под ключ, запуск,
  закупки, помещение в 3D), `templates/` (юнит-экономика, HTML-бизнес-план). Грузится один файл, не весь скилл.
- **Российская специфика — живые данные:** режимы (самозанятый/ИП/УСН/патент/ООО), взносы, НДС, кассы, маркировка,
  блокировки счёта по 115-ФЗ, реклама и персональные данные. Даты и редакции сверяются при каждом запросе.
- **Грань достаточности:** малому бизнесу не нужен Porter на 40 страниц — минимальный фреймворк, одна проверяемая
  гипотеза, один эксперимент, одна цифра.

### Обоснование (замер, не обещание)

`eval/results.md` — слепой A/B: те же 3 бизнес-вопроса без скилла и со скиллом, судья Qwen3.6-35B, рандом-маппинг.
Итог **72/75 со скиллом против 70/75 без** — near-parity. Выигрыш там, где скилл явно называет узел и даёт формулы
(runway, валовая маржа); на знаменитых книгах модель и без скилла отвечает сильно. Отдельные замеры:
тест автозапуска (12/12 на своих вопросах про налоги против 0/12 у старого описания и 12/12 молчания
на чужих — МППСС, ипотека, акции, мотивация, копирайт, личный налог) и слепой тест терминов
(50 терминов, 28 «мёртвых» составных — отсюда правило «грепай по одному слову»). Не покрыто: стабильность структуры
на длинной дистанции и реальный юз — поэтому вердикт замера честный: «ядро работает, форму дальше не полируем».
