# Маршрут разработки

Оркестратор: ведёт приложение пользователя по 8 этапам, на каждом этапе — свой исполнитель.
Методика — стрим Сергея Шимы «Как писать код с ИИ-агентами: от ТЗ и PRD до приёмки кода»
(https://www.youtube.com/watch?v=uY1bTL1i2DM) + поправки разбора (что он сам назвал упущенным).

## Ядро: забор
Следующий этап не начинается, пока в текущем есть пустой чекбокс. Это механизм, не обещание.
Скрипт лежит рядом с этим файлом — `scripts/route.py` (путь строить от папки скилла):

```bash
python3 <папка-скилла>/scripts/route.py init <папка-проекта>/ROUTE.md --name "Имя" --track full|lite|feature
python3 <папка-скилла>/scripts/route.py status <папка-проекта>/ROUTE.md   # текущий этап и что открыто
python3 <папка-скилла>/scripts/route.py gate <папка-проекта>/ROUTE.md <N> # перед этапом N; exit 1 → стоп
```

- `gate` проверяет и галочки, и файлы этапа (BRIEF.md, RESEARCH.md, GRILL.md, PRD.md + CONTEXT.md + PHILOSOPHY.md,
  REVIEW.md, CHECKLIST.md) рядом с ROUTE.md: галочка без файла — этап не закрыт.
- Перед КАЖДЫМ этапом — `gate`. Exit 1 → показать пользователю открытые пункты, этап не начинать.
- Пункт отмечать `- [x]` только по факту (файл есть, проверка прошла). Последний пункт этапа —
  только после слов пользователя «этап закрыт» / «да».
- Пользователь хочет перескочить → сказать, какой пункт открыт и чем рискуем; перескок — только его
  явным решением: последний пункт этапа заменить на `- [~] пропущено пользователем: <причина> (дата)`.
  Забор считает такой этап закрытым и файлов этапа не требует (остальные пункты — тоже `[~]`).

## Конец любой сессии
Отметить `ROUTE.md` → `HANDOFF.md` рядом с ним (что сделано, что не сделано, что дальше, какие файлы
читать) → `/compact`. На любом этапе и в любом треке; следующая сессия начинает с `status` и `HANDOFF.md`.

## Треки
- `full` — 1–8: приложение с ролями, данными, интеграциями.
- `lite` — 1, 3, 4, 6, 7, 8: мини-приложение на вечер (без исследования и второго мнения).
- `feature` — 3, 4, 5, 6, 7: новая фича в живой проект, своя папка `features/<фича>/ROUTE.md`.
Трек предлагаешь ты по брифу, выбирает пользователь.

## Этапы
Что на входе, что делать, что на выходе — `references/stages.md`. Пункты — `references/route-template.md`.
Прожарка (этап 3) — отдельный скилл `grilling`: вызвать через Skill.
Словарь и тесты — исходники Мэтта Покока в `references/pocock/` (MIT, репо `mattpocock/skills`
@ c55ee46, 2026-09-18), слово в слово: перед этапами 3 и 4 открыть `domain-modeling.md`, перед 7 —
`tdd.md` целиком и вести строго по ним, не по памяти.

## Пользователь
Может не быть программистом. Код не читает — читает бриф и пользовательскую часть PRD.
Вопросы — раундами по 3–5, у каждого рекомендованный ответ.
