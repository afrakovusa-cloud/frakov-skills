# Симуляция рисков — прожить бизнес тысячу раз до вложений

Бизнес-план на средних цифрах врёт систематически: «в среднем 6 выездов в месяц» не видит, что в пятницу пришло 3 заявки на один комплект, а в январе ноль. Симуляция разыгрывает случайность по дням и показывает распределение исходов: как часто бизнес окупается, как часто кончаются деньги, какая одна цифра решает всё.

Когда нужна: крупная разовая ставка (закупка оборудования, аренда помещения на годы), сильная сезонность, ограниченная мощность (один комплект, одна точка, одна бригада). Мелкий тест за 50 тыс. — не нужна, проверить дешевле, чем моделировать.

## Порядок (из канона, шаг = книга)

1. **Пороги: «What would have to be true?»** (Playing to Win, гл. 8, `grep -in "have to be true" source-book/playing-to-win.md`). Не спорить «окупится ли», а спросить: что должно быть правдой, чтобы окупилось за N месяцев? Модель ищет пороги (≥ X продаж/мес при цене ≥ Y). Самое маловероятное условие — первое на тест.
2. **Разметить входы: проверено vs leap-of-faith** (The Lean Startup, `grep -in "leap-of-faith" source-book/the-lean-startup.md`). Каждый вход — диапазон, не число. Помечать, откуда: факт (КП, прайс конкурента, курс ЦБ) или прыжок веры (спрос, конверсия, повторные). Прыжки веры и дают самые широкие диапазоны.
3. **Разыгрывать по дням с колебаниями, не на средних** (The Goal, игра с кубиком и спичками, `grep -in "statistical fluctuations" source-book/the-goal.md`). Колебания + зависимые события (одна мощность на день) = потерянные заказы, которых нет в средних. Отдельно считать «сгоревшие» заявки — это цена узкого места.
4. **Чувствительность 80/90% и кассовый разрыв** (Financial Intelligence, `grep -in "sensitivity analysis" source-book/financial-intelligence.md`; сценарий «profit without cash»). Обязательный стресс: выручка ×0,8. Отдельно — минимум денег на счёте по месяцам: прибыльный на бумаге бизнес умирает, если закупка оплачена до сезона.
5. **Baseline после теста** (The Lean Startup, innovation accounting, `grep -in "baseline" source-book/the-lean-startup.md`). После дешёвого MVP (субаренда, предзаказы) заменить прыжки веры реальными цифрами и перегнать. Модель без калибровки — гипотеза, с калибровкой — инструмент решения.

## Сам метод Монте-Карло — вне канона

В `source-book/` его нет (grep «monte carlo», «simulate» = 0, проверено 2026-09-29). Опора вне канона: «How to Measure Anything» (Hubbard) — диапазоны неизвестного и Монте-Карло для решений; «The Flaw of Averages» (Savage) — почему план на средних врёт. См. `../booklist.md` → «Дыры канона».

Механика: N прогонов (1 000–10 000), в каждом случайно берутся значения входов из диапазонов и разыгрываются дни → на выходе P10 / P50 / P90 (плохой / средний / хороший — это перцентили исходов, не придуманные сценарии).

## Выход модели (обязательный набор)

- P10 / P50 / P90 накопленных денег по месяцам (веер).
- Вероятность окупиться за 24 / 36 мес.
- Вероятность кассового разрыва (деньги на счёте < 0 хоть в одном месяце).
- Доля сгоревших заявок (узкое место, шаг 3).
- Торнадо: какой вход сильнее всего двигает итог → его тестировать первым.
- Стресс-кнопки: курс +30%, выручка ×0,8, пустой месяц + поломка, демпинг конкурента.
- Пороги из шага 1.
- **Стратегии рядом, а не одна.** Минимум: своё новое / аренда-субаренда без вложений / б/у / меньший масштаб / маршрут «сначала без вложений → покупка по правилу». Сравнивать по итогу за горизонт **плюс остаточная стоимость актива** — без неё аренда всегда выглядит лучше покупки (урок 2026-09-29, LED).
- **Условный маршрут моделировать с правилом решения** («покупаем, если к месяцу N ≥ X продаж»), иначе модель покупает всегда и теряет смысл опциона. Порог X подбирать прогоном по сетке.
- **Устойчивость к главному прыжку веры:** прогнать стратегии при слабом / ожидаемом / сильном значении самого шаткого входа. Пока вход не проверен, выбирать стратегию, которая нигде не проваливается, а не лучшую в середине.

## Граница честности

Модель считает только заложенное. Она не доказывает спрос — она показывает, **какую цифру проверить в реальности первой**. Выдавать P50 за прогноз — ошибка; это «середина при наших допущениях».
