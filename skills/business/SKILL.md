# Бизнес — операторские фреймворки

Строй бизнес как **проверяемую машину**, а не как «идея плюс усилия». Машина = 5 узлов: **стратегия → оффер/привлечение → операции → финансы → люди/масштаб**. Сбой ищи по узлам, не по настроению. Опора — канон операторских книг (`references/booklist.md`), синтез по темам, а не пересказ по книгам.

**Тексты книг лежат локально** (`references/source-book/`, куплены владельцем). Нужен точный факт/цитата/цифра из книги — не по памяти, а **grep по source-book** (карта «тезис → файл» в `references/source-map.md`). Пример: `grep -in "value equation" references/source-book/100m-offers.md`. Пути в файлах `references/` (`source-book/…`, `../source-book/…`) — относительно своего файла; из корня vault грепай по полному `.claude/skills/business/references/source-book/<файл>.md`. Функции ниже — индекс-выжимка; source-book — первоисточник.

## Рабочий контракт

> ⚠️ **ГЛАВНОЕ ПРАВИЛО (архиважно, не пропускать НИКОГДА).** Любой бизнес-разбор/совет/анализ строится **из книг**, не из головы. Перед выводом:
> 1. Определи узел → метод → **grep нужный метод в `references/source-book/`** (карта `source-map.md`).
> 2. **Назови книгу и приём явно** («по методу X из <книга>»), приведи опору из текста.
> 3. Применяй метод дальше — в т.ч. лезь в веб (конкуренты, рынок, цифры) **через призму этого приёма**, а не по наитию. Веб для плана/разбора — скилл `deep` (`mcp__search__deep_research`, все провайдеры параллельно), не одиночный `web_search`: на рюмочной Сыктывкар 2026-10-04 дип на тех же запросах нашёл региональный закон о зале ≥ 50 м² в жилом доме, позицию Росалкоголя по настойкам и местных конкурентов — `web_search` всё это пропустил. `web_search` — только сверка одного факта. Все провайдеры в таймауте → это сеть, не скилл: повторить позже, в плане пометить «не проверено».
>
> В карте нет строки под вопрос или grep пуст → не сдавайся: переведи вопрос владельца в 3–5 английских терминов автора (книги на английском, вопрос по-русски) и грепни по `source-book/`.
> **Грепай по одному слову, не по фразе.** Красивые составные термины модель выдумывает: в замере 2026-09-24 из 50 слепых терминов 28 не встречались в книгах ни разу (`risk reversal`, `fake door test`, `survivor guilt`), а те же наборы, разбитые на отдельные слова, живые почти все. Ищи `guarantee`, `severance`, `layoff`, `one-on-one` — не `risk reversal` и не `layoffs done right`.
> Пусто по ОДНОСЛОВНЫМ вариантам всех терминов — только тогда «в каноне этого нет».
>
> Нет опоры в source-book под тезис → так и скажи «в каноне этого нет, ниже — вне книг». Отвечать «из памяти» под видом книги — запрещено. Это относится ко ВСЕМ узлам, не только к конкурентам.

1. Сначала факты о конкретном бизнесе: цифры (выручка, маржа, CAC, отток), кто клиент, что уже пробовали. Не давай совет «вообще» — привязывай к его числам.
2. Разделяй:
   - **факт** — что подтверждено цифрой/договором/повторяемым наблюдением;
   - **гипотеза** — вероятное объяснение, требует проверки;
   - **неизвестно** — что надо измерить/спросить.
3. Начинай с решения или диагноза. Потом — минимальный план и как проверить, что сработало.
4. Никакой мотивации и «верь в себя». Только механика: что сделать, какая цифра должна сдвинуться, за какой срок.
5. **Прозрачность: каждое утверждение проверено первоисточником или помечено.** Книжные фреймворки — эвристики, не законы; рынок, цены, регуляторика — только из текущих источников, и источник обязан быть того уровня, что утверждение:
   - **Закон, норма, штраф, срок, госпошлина** → открыть **текст самого акта** (pravo.gov.ru / publication.pravo.gov.ru, КонсультантПлюс, Гарант, сайт ведомства) и сверить номер, редакцию, дату вступления. Новость, блог юристов, сайт посредника — только наводка, не факт. Пример: «зал ≥ 50 м²» на рюмочной 2026-10-04 взяли из новости Комиинформ 2023, текст 34-РЗ не открыли.
   - **Цена, аренда, зарплата** → ≥ 2 живых объявления/прайса со ссылкой и датой; иначе `оценка`.
   - **Рецепт, техническая цифра, норматив оборудования** → паспорт, ГОСТ/СанПиН, техкарта производителя; иначе `оценка, проверить`.
   - Каждое утверждение в выдаче несёт метку `факт (источник, дата)` / `оценка` / `гипотеза` (формат меток — `playbooks/full-plan.md`, п. 4). Первоисточник не открылся (сеть, блок) → `не проверено`, не «факт».
   - **Ворота перед отправкой:** `python3 .claude/skills/business/scripts/check_facts.py <файл>` — код ≠ 0 → каждую строку `✗` либо проверить по первоисточнику, либо понизить до `оценка`/`не проверено`, прогнать снова до кода 0. Скрипт ловит `факт` без источника и закон без «сверено по тексту»; верность источника не проверяет. Отправку HTML из `Приложения/Бизнес/` скриптом с `send_file` хук `.claude/hooks/bash-guard.py` блокирует сам, пока код ≠ 0. Список непроверенного — отдельным блоком в выдаче и в ответе владельцу.
6. Быстрый вопрос (термин, формула, одна цифра, «что почитать») — ответ ≤ 800 слов: решение, число, следующий шаг; не вываливай весь чеклист. Разбор/план — глубокий формат (раздел «Формат по умолчанию»), лимит 800 слов на него не действует.
7. **Эскалация пробела базы** (правило `kb-gap`). Пометил «в каноне этого нет» (см. ГЛАВНОЕ ПРАВИЛО) и это узнаваемый повторяемый приём (не разовая местная конкретика) — не останавливайся на пометке: предложи дописать в `references/functions/` или добавить книгу в `booklist.md`. База растёт там, где были дыры. Разовую нишевую конкретику (местный рынок, частный случай) в базу не тащить.

## Формат по умолчанию — глубокий разбор

Владелец в восторге от глубокого разбора La Fete (2026-08-28): «офигенно, в таком формате
всегда делай». Разбор/план по умолчанию — глубокий, не спрашивать «покороче или поглубже».
Ему заходит не «совет вообще», а обоснованный цифрами разбор с понятной картиной рынка и
приоритетами — «на единичку» (общие буллеты) не заходит. Состав и порядок разделов —
единственный источник `references/playbooks/full-plan.md` → «Стандарт глубины» и «Обязательные
числовые блоки»; выдача — «Маршрут доставки владельцу» ниже. Мельчить — только если задача явно
крошечная.

## Маршрут доставки владельцу

Разбор собирается и доставляется одним маршрутом (обкатан 2026-09-24 на четырёх разборах по
Эжве: вендинг, закупочный лист, 3D-печать, медиа) — просьба «посчитай бизнес / собери план /
сравни варианты» сразу идёт этим маршрутом, не спрашивая формат:
1. **Глубина** — `references/playbooks/full-plan.md` (см. выше).
2. **Форма** — HTML по `templates/plan.html`, файл в `Приложения/Бизнес/`, имя `YYYY-MM-DD <тема> — <что>.html`.
3. **Доставка** — Telethon `send_file("me", path, force_document=True)` с **копии** сессии
   (см. скилл `telegram`, `references/tools.md`, «Отправка файлов»). В подпись — вердикт,
   ключевая цифра и главный риск: владелец читает с телефона и файл может не открыть сразу.
4. **В чат** — та же суть текстом с эмодзи-заголовками. Файл в чате он не видит, поэтому путь
   + выжимка обязательны.
5. **Третьему человеку** (не «me») — только после трёх стоп-точек: `check_facts.py` = 0 → файл
   в Избранное (п. 3) → «да» владельца на этот файл. Урок 69: рюмочная ушла Юле напрямую, ~19
   шагов без проверки, ошибку «50 м²» владелец поймал уже после отправки.

**Why:** владелец в рейсе, читает с телефона, файлы через мост не проходят. HTML открывается в
браузере, печатается в PDF и переживает сессию, а Markdown в чате теряется.
**Отвергли:** ответ только текстом в чат (теряется между сессиями); Markdown-файл в vault без
отправки (владелец до него не дойдёт); MCP telegram-mtproto для отправки — умеет текст и фото,
документы не тянет.
**Пересмотреть если:** мост научится отдавать файлы в чат сам — тогда Telethon-копия сессии
станет лишним звеном.
Веер идей перед разбором — скилл `inventor` (5 вариантов, 2 хвоста), дожим формулировки —
`phrases`.

## Ядро: бизнес как машина

> **Бизнес = кто-то платит больше, чем стоит его обслужить, повторяемо.**

Разложи в 5 узлов и проверяй по одному:

1. **Стратегия** — где играть и почему именно ты выигрываешь (устойчивое преимущество, не «лучше стараемся»).
2. **Оффер/привлечение** — насколько ценность > цены в глазах клиента, и по какому каналу они приходят предсказуемо.
3. **Операции** — работает ли оно без основателя; где узкое место, ограничивающее выпуск.
4. **Финансы** — сходится ли на единице (юнит-экономика) и не кончается ли кэш.
5. **Люди/масштаб** — рычаг менеджера, найм A-игроков, что ломается при росте ×10.

**Правило локализации сбоя:** «не растёт / не зарабатывает» → пройди узлы по порядку. Нет спроса (2) важнее плохих операций (3). Дырявая юнит-экономика (4) убивает раньше, чем стратегия (1). Не чини узел 3, пока не подтверждён узел 2.

## Грань достаточности

Малому бизнесу не нужен Porter Five Forces на 40 страниц. Бери минимальный фреймворк, который двигает решение: одна проверяемая гипотеза → один эксперимент → одна цифра. Разворачивай тяжёлую артиллерию (7 Powers, теория ограничений) только когда простое не объясняет провал.
